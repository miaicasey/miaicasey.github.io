Heidi feels built for every market it sells into, and the string pipeline catches gaps before clinicians do.

Context

About 54,000 clinicians a week arrived from non-English regions and 71.6% dropped at the first sign-in screen. Language did not carry from the marketing page into the product, the i18n library had no ICU support, every clinician in every country picked from the same 300-item specialty list, and Arabic needed a right-to-left interface Heidi had never built.

Problem

Make Heidi feel built for every market it sells into, and make the string pipeline catch gaps before clinicians do.

Discovery and explorations

I ran the localisation planning cadence with the Localisation Lead and led the Linear projects. Foundation first: BCP-47 locale identifiers, a react-intl migration, an i18n linter, a translation detection CLI, a scheduled Crowdin sync, pseudolocalisation devtools. Then the experience: language carried end to end, a per-region compliance matrix and badges I audited myself, demo booking by region with a phone fallback, specialty lists filtered by country, EHR dropdowns per market. For Arabic I flagged from the start that it needed a full UI adaptation, created the coordination channel, pulled design in, drafted the RTL milestone tickets (UI audit, typography, icon directionality, component specs, design QA) and ran the AI scan of untranslated strings and direction-unsafe patterns before rollout.

Design collaboration and QA

The RTL work was the deepest design collaboration in this stream: I wrote the component specs with the Principal Product Designer and ran the design QA pass. We did not get a single design QA ticket on the first rollout.

Impact

  • Language now carries end to end; before this GTM configured country, billing, timezone and language by hand for every DACH customer.
  • Japanese clinicians stopped seeing “Aboriginal Mental Health Worker” the day the specialty country filter shipped.
  • The i18n scanner flagged 54 English source strings for rework; I triaged a 24,248-gap report to three missing locales and a 97% false positive rate on the rest.
  • Japan’s launch-critical list closed before the first conference: family-name-first ordering, a doctor-reviewed list of 121 specialties, a 15-vendor EHR dropdown, ja-JP date standard.

Reflection

Flagging at the start that Arabic needed the design system to change rather than a translation swap is the single call that made the launch go clean, and it is the pattern I would apply to any market with a structural difference from the base product.

I would change the sequencing. We fixed the string pipeline and the language carry-through in parallel with the regional experience work, and the foundation should have landed first. Too many specialty and EHR fixes were done twice, once before the linter and the locale identifiers existed and once after. I would also set the four Japan foundation patterns before the launch rather than after, so each Growth release stopped reopening the launch-critical list.

The triage habit is the one I carry forward. A report of 24,000 gaps sounds like a crisis until you find three missing locales and a 97% false positive rate, and that kind of reading saved weeks of translator time.
